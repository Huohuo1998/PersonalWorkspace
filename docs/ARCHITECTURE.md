# 实施架构与业务不变量

| 层 | 实现 |
|---|---|
| Web | React 19 + TypeScript；Vite；React Router；TanStack Query；Lucide；系统中文字体和 CSS tokens |
| API | FastAPI / Pydantic；同域 `/api/v1`；规范化错误、request ID；OpenAPI |
| 存储 | PostgreSQL 16；SQLAlchemy 2；Alembic 版本化迁移 |
| 认证 | Argon2id 密码哈希；随机会话令牌仅 Cookie；数据库仅存 SHA-256 令牌哈希；可撤销会话；CSRF 校验 |
| 部署 | Caddy HTTPS → nginx 静态前端 / 同域 API 代理 → FastAPI → 私网 PostgreSQL |

## 领域

`backend/app/models.py` 定义独立任务/事件/项目、交易/账户分录/预算/储蓄、训练会话/实际组、食谱/菜单/采购快照/真实用餐及审计/幂等操作。运动轻量对象（动作、模板、安排、自由运动、身体测量）在 `entries` 内使用区分类型的 JSON，由 Pydantic 严格校验，再与 `user_id`、版本及时间持久化。

所有业务检索、变更、关联都带授权用户范围。客户端传入其他人的 UUID 不会授权访问；对不可访问对象统一 404。不可指定 `user_id`。跨模块源引用检查所有权，引用失效不会删除已有业务事实。

## 财务

账户没有客户端可覆盖的余额缓存。余额从持久化 `account_movements` 求和，金额使用 `NUMERIC` / Decimal。API 的金额返回十进制字符串；显示层才格式化。

净债务 C 为正代表欠款，为负代表溢缴；净资产 = 资产余额 − 信用净债务。欠款与溢缴互斥呈现，不双计。转账、还款、期初和校正不计收支；消费发生时计支出，退款在实际到账月份冲减原分类，且只改变真实目的账户。退款总额不得超原消费，相关原交易在事务内核对。

所有高风险写入使用幂等标识，按用户唯一，并比较请求内容哈希。操作响应和分录同事务提交。相同键相同内容回原结果；不同内容返回 409。超时查询 `/operations/{key}`，未知不自动重发。账户版本变动使核对失效；负余额和溢缴要求明确风险核对。交易历史不无痕覆写，校正另留审计与分录。

## 并发与事务

变更请求在 PostgreSQL 锁定当前用户行，同用户变更串行化。这是个人规模的简单一致性选择；跨用户仍并发。账户、训练组、采购项显式版本核对。数据库部分唯一索引保证一个活动/暂停详细训练和一个专用账户活动储蓄目标。资金分录、业务记录、审计、幂等响应统一提交；FastAPI 依赖使用 function scope，使数据库 commit 失败时不会先发送成功。

MVP 运行 PostgreSQL，不用 SQLite 模拟这些并发保证。扩大负载前可将用户锁细化为资源锁并保留原测试。

## 训练

仅一个详细会话处于进行中/暂停；快速运动独立。模板复制为快照组，历史不受模板编辑影响。组修改延迟 700ms 自动保存，服务器确认才显示 saved，失败保留当前页面输入并禁用结束。冲突显示服务器值，用户明确选择采用服务器或重新保存本端值。结束核对会话版本及**完整组版本集**，只统计实际完成组。源任务只能在明确关联且真实完成有实际组时闭环，手动完成日程不会反造训练。

## 饮食与采购

菜单不创建用餐事实，预填表单取消不插入记录；实际来源标为自炊才能计自炊。食谱可手动维护；三份基础食谱需用户明确导入，并注明过敏信息边界。采购勾选不产生交易。

同名食材、规格、兼容量纲才聚合：kg→g、L→ml；件数需同一明确规格。未知袋重、适量、跨量纲不猜算。采购保存 N（理论）、P（已购）、U（待购）、manual_override 和 uncertain。差异只预览；确认时校验菜单/食谱/清单哈希和版本。自动项新待购 = max(0,N−P)，补购 = max(0,N−P−U)。人工/未知项保护，已购事实保留；同轮幂等应用不重复补购。

## 日程与时间

任务四种生命周期与 inbox 位置分离；执行日期/时点与截止日期独立。日/周重复任务滚动实例化，以模板 ID + occurrence_key 唯一，遇到已有实例不改写，保持历史和单次调整。事件是独立时间范围，不是勾选任务。用户时区用于「今天」和瞬时值展示；账务/实际用餐记录使用明确日期。事件输入按浏览器本地时区解释，表单显式注明，存储带时区时间。

## 客户端状态与隐私

首页独立请求日程/财务/运动/饮食，单域失败不把其他域清空。加载中、空、真实零、失败、保存中、确认成功、结果未知分别呈现，不填假数据。401 后隐藏敏感输入并回登录；离线显示联网要求，无离线自动同步承诺。

隐私偏好持久化在用户账户。`Sensitive` 在遮蔽时**不渲染其子内容**，覆盖金额、账户负数提示、预算进度、身体/恢复和训练表现摘要；不存在隐藏在 tooltip 或 aria 标签里的金额。当前主动编辑字段按 POL-PRIV-01 保持可读，偏好不因此关闭。隐私遮蔽不替代鉴权。
