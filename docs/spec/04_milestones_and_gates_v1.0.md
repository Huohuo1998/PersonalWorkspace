## 2. 三个建议的纵向切片

1. **Slice A：Task 真实端到端**：浏览器登录 → 创建任务 → 收集箱 → 安排今天 → Dashboard → 刷新仍存在 → 401/404/保存失败演示验证。先校验整个前后端和用户边界。
2. **Slice B：资金真实端到端**：创建账户 → 一次消费 → 账面变更 → 信用卡消费/还款/跨账户退款 → 重新加载后汇总一致 → 网络超时不重复记账。先把最难的一致性保护做正确。
3. **Slice C：训练或采购恢复端到端**：组自动保存 + 刷新恢复 + 两设备冲突；或采购生成→已购→变菜单→核对补购→再次核对无重复。

## 3. Definition of Done（未来开发使用）

每项交付必须满足：

- 能追溯到已确认的 PRD/UX/视觉与唯一验收编号。
- 前端的空/零/加载失败、保存中/已保存/失败状态符合设计。
- API Schema、数据迁移、权限范围、边界校验均完成且受测试保护。
- 相关 P0 用例通过自动化或明确的手工验收，未通过项不可伪装完成。
- 数据变更支持必要的审计与可恢复策略；数据库备份/还原具备实际演练证据。
- 手机布局至少检视 320、360、390、430px；系统字体放大、触控和软键盘不会遮挡关键操作。
- 安全日志不打印口令、会话令牌或敏感身体/财务明文。

- 已完成 S1 技术选型及关键数据口径审核；部署目标和数据存储位置明确；必要安全政策有负责人。
- S0 未关闭的原始 PRD 全文缺口明确作为风险登记，不伪称已完整回收。
- 开发范围、仓库位置、技术栈及阶段目标通过用户显式授权。
- 未取得该授权时仅能创建或修改技术设计文档，不能生成网站仓库、安装依赖、执行数据库迁移或部署站点。
