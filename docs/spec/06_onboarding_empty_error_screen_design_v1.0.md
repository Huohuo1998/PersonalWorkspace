# Personal Workspace｜首次使用、空状态与系统异常页面设计 V1.0

> 日期：2026-10-12  
> 状态：**页面规格设计稿，待高保真与可访问性验证**  
> 依据：四个领域已确认 PRD、全站 UX V1.1、视觉基线 V2.0，及 `02_critical_flows_and_edge_cases_v1.0.md`、`05_p0_exception_screen_design_v1.0.md`。  
> 当前阶段：**只设计，不开发、不实现身份验证、不连接真实用户数据。**

## 0. 范围、冻结规则与术语

本轮设计三类页面及其返回路径：**首次使用**、**没有数据时的页面**、**系统与权限异常页面**。不新增一级导航、通用打卡模块或强制初始化流程，也不重写已确认的领域业务规则。

- **首次使用 ≠ 首次建齐所有数据**：欢迎引导可跳过、可暂时关闭，领域操作按需完成最小必要配置。
- **数据为空 ≠ 结果为零 ≠ 查询失败**：三种状态的视觉文案、操作入口和数据可靠性不同。
- **操作失败 ≠ 提交结果未知**：普通输入保存失败允许纠错/重试；资金、训练结束等可能已经生效的请求不得鼓励盲目重复提交。
- **无权限 ≠ 没有记录**：不展示私有资源片段、对象标题、金额、存在性或内部标识。
- **来源失效 ≠ 目标操作失败**：明确区分目标业务是否已经成功，并提供安全返回路径。
- `SCREEN-ONB-*`、`SCREEN-EMPTY-*`、`SCREEN-ERR-*`、`SCREEN-AUTH-*` 是**界面规格标识**，不是 URL、API、代码模块或数据模型。

### 0.1 通用页面状态词汇

| 状态 | 数据含义 | 页面处理 | 禁止的处理 |
|---|---|---|---|
| 初始加载 `loading` | 尚未获得可信返回 | 与最终布局接近的骨架/简洁进度，必要时可取消 | 假装余额为 ¥0、任务 0 项 |
| 真实空集合 `empty` | 查询成功且集合确实为空 | 说明没有记录，给出直接行动入口 | 用“同步失败”制造虚假故障 |
| 真实零值 `zero` | 查询成功，测量/金额/计数确实为零 | 合法地显示 0、¥0.00 或 0 次，并显示口径 | 写成“尚未设置”，或用占位数替代 |
| 已配置但暂无本周期数据 `no-period-data` | 数据存在，当前周期无事实记录 | 显示当前周期暂无记录，可切换周期 | 将历史数据归零或误写成从未使用 |
| 局部失败 `partial-error` | 个别领域数据获取失败 | 有效卡片照常展示，失败卡片独立重试 | 删除已返回的真实数据或显示假总体 |
| 加载失败 `load-error` | 当前数据无法可靠获得 | 原位错误提示、重试、可用的安全退路 | 以零值/空状态代替错误 |
| 保存失败 `save-error` | 用户修改未成功持久化 | 保留编辑内容，显示失败与恢复方式 | 直接显示“已保存” |
| 结果未知 `unknown-result` | 提交可能已生效但未得到确认 | 核对原请求状态，防止重复操作 | 再次创建等价资金/运动/用餐事实 |
| 禁止访问 `forbidden` | 无权访问目标资源 | 拒绝显示敏感信息，提供安全入口 | 显示资源的标题、金额或是否存在 |

## 1. 首次使用流程｜非强制、渐进式

### 1.1 导航流程

`SCREEN-ONB-01 欢迎入口` → 选择 `直接开始` / `跳过进入首页`：

- `直接开始` → `SCREEN-ONB-02 选择第一件事` → 跳入一个已有领域入口。
- `跳过` → Dashboard；四个领域可以独立保持空状态，无红色待办、强迫评分或强制补完。
- 登录后并非首次也可以通过领域空状态和全局 “+” 执行第一件事；不要因为关闭欢迎页而丧失功能。

**欢迎页不是长期待办清单**：完成任何一个起步操作后，可以返回 Dashboard。不要强行推进另一个模块的配置。

### 1.2 页面规格

| 屏幕 | 页面主要内容 | 主操作 | 次要操作 | 桌面/手机差异 |
|---|---|---|---|---|
| `SCREEN-ONB-01` 欢迎入口 | 简短欢迎语、四个可选起步领域、“以后再说” | 选择想做的第一件事 | 跳过欢迎 | 桌面居中内容容器；手机独立欢迎页，不层层叠弹窗 |
| `SCREEN-ONB-02` 首个行动 | 新增任务 / 创建账户后记账 / 记录散步 / 记录实际用餐 | 打开对应领域的真实表单流程 | 返回欢迎页或首页 | 手机入口采用大触控卡片 |
| `SCREEN-ONB-03` 财务最低配置 | 说明记账需要一个真实资产或信用账户；提供新增账户入口 | 创建首个账户 | 返回经济概览 | 只收集账户必要字段；不强制录入预算和储蓄目标 |
| `SCREEN-ONB-04` 起步完成返回 | 已确认成功的操作摘要、下一步入口 | 返回原来源或首页 | 留在对应领域 | 只在操作得到真正保存确认后展示完成 |

### 1.3 各领域的最小起步条件

| 领域 | 可直接做的第一件事 | 硬性前置条件 | 禁止作为强制前置条件的内容 |
|---|---|---|---|
| Schedule | 一句话新增任务并进入收集箱；新建事件 | 任务标题；事件所需时间 | 先建项目、填优先级、填截止时间 |
| Finance | 新增账户，然后做第一笔真实收支记录 | 合法有效的记录账户；实际金额、日期等必要字段 | 先录入全部账户、预算或储蓄目标 |
| Fitness | 直接记录散步/跑步等已完成自由运动 | 实际运动的必要记录字段 | 先创建目标、训练模板或身体测量 |
| Diet | 快速记录实际用餐 | 餐次、实际内容和必要日期 | 先建立食谱、菜单、采购清单或营养目标 |

如用户从全局快捷入口点击“快速记账”且没有账户，进入 `SCREEN-ONB-03`，成功创建账户后**返回尚未完成的记账上下文**，而不是要求用户重新从首页找到该操作。若用户取消账户创建，则不生成交易。

### 1.4 首次引导的视觉文案

- 标题：“从一件小事开始。”
- 说明：“不用一次设置好所有模块，随时可以再回来。”
- 主操作：“记下一件待办”“记录一次运动”“记录今天吃了什么”“开始管理收支”。
- 次要操作：“暂时跳过”。
- 禁止：“请完成 4/4 项设置才能开始”“连续零天，落后目标”。

## 2. 空状态｜按数据含义提供对应入口

**统一空状态组件**：识别图标、简短标题、解释为何为空、一个主要可执行入口、必要的次级了解入口。不要用大型装饰图占据大半手机首屏，不要把不适用的编辑入口显示为可用。

| 屏幕 | 触发前提（可信查询成功） | 标题/说明 | 推荐主操作 | 需要区分的边界 |
|---|---|---|---|---|
| `SCREEN-EMPTY-01` Dashboard 新用户 | 各领域均尚未有有效摘要数据 | “从一件小事开始” | 全局快捷新增任务 | 各模块独立为空，不合成虚构完成率 |
| `SCREEN-EMPTY-02` 今日无安排 | 今日无定时事件、今日重点/截止事项 | “今天还没有安排” | 新增任务/事件 | 逾期事项在待关注而非偷偷改到今日 |
| `SCREEN-EMPTY-03` 收集箱已清空 | Inbox 没有待整理事项 | “收集箱整理好了” | 快速记下一件事 | 收集箱不是 `COMPLETED` 业务状态 |
| `SCREEN-EMPTY-04` 任务筛选无结果 | 有数据但筛选后 0 条 | “当前条件没有匹配的任务” | 清除筛选 | 不提示“创建第一项任务” |
| `SCREEN-EMPTY-05` 经济未建账户 | 当前用户没有可用账户 | “先创建一个账户” | 新增账户 | 不显示 ¥0.00 总资产作为真实余额 |
| `SCREEN-EMPTY-06` 当月无交易 | 已有账户、当月无交易 | “这个月还没有交易” | 快速记账 | 账户仍有真实余额，不能暗示无资产 |
| `SCREEN-EMPTY-07` 未设预算 | 没有本月预算 | “本月还没有设置预算” | 设置预算 | 预算未设置 ≠ 预算为 ¥0.00 |
| `SCREEN-EMPTY-08` 无储蓄目标 | 未创建目标或未关联专用账户 | “还没有储蓄目标” | 创建目标/查看要求 | 不自动创建虚拟资金 |
| `SCREEN-EMPTY-09` 无训练计划 | 当前无生效计划 | “还没有训练计划” | 创建/选择计划 | 自由运动仍可记录 |
| `SCREEN-EMPTY-10` 无训练历史 | 已加载历史，确实无会话/记录 | “还没有运动记录” | 记录一次自由运动 | 不能把计划任务完成计入实际训练 |
| `SCREEN-EMPTY-11` 无身体记录 | 无体重、腰围或恢复条目 | “按需要记录身体状态” | 可选添加测量 | 不强制填写，不显示无依据的趋势图 |
| `SCREEN-EMPTY-12` 食谱无匹配 | 筛选后无安全匹配候选 | “没有符合当前条件的食谱” | 调整筛选 | 不放松用户明确食材禁忌来增加结果 |
| `SCREEN-EMPTY-13` 未安排菜单 | 所选日期/周期没有计划餐食 | “还没有安排这天的菜单” | 添加一餐 | 实际用餐仍可独立记录 |
| `SCREEN-EMPTY-14` 尚未生成采购单 | 尚无采购快照，或本周没有结构化需求 | “还没有采购清单” | 从菜单生成/手动添加 | 自由文本菜单不可强行计算食材 |
| `SCREEN-EMPTY-15` 没有实际用餐历史 | Meal Record 查询成功为空 | “还没有实际用餐记录” | 快速记录一餐 | 不能把计划菜单当作已吃 |

**特殊情况**：如果预算真实配置为 0 元、但已有消费，显示真实预算配置与超额情况；如果消费净额因退款成为负值，显示合法的负值及说明，不擅自截断为 0。若没有身体测量，不绘制从零开始的体重趋势。

## 3. 系统异常与权限页面

### 3.1 屏幕规格

| 屏幕 | 触发条件 | 显示原则 | 推荐行动 | 不得发生 |
|---|---|---|---|---|
| `SCREEN-ERR-01` 全页加载失败 | 核心页关键查询失败 | 原位错误标题、简洁原因、重试 | 重新获取当前页 / 返回模块 | 以空数据冒充查询成功 |
| `SCREEN-ERR-02` 模块局部加载失败 | 首页部分领域摘要失败 | 未失败摘要仍可见；失败卡片单独提示 | 重试该卡片 | 以局部失败抹去其他领域真实数据 |
| `SCREEN-ERR-03` 普通表单保存失败 | 请求确实失败且未生效 | 保留编辑值；指出错误字段或连接问题 | 修正或重试本次保存 | 清空输入、显示“成功” |
| `SCREEN-ERR-04` 非幂等操作结果未知 | 交易/训练结束/记录创建等提交超时且不知是否成功 | “无法确认本次结果”，保留同一请求上下文 | 查询/核对原提交结果 | 立即创建第二笔相同业务事实 |
| `SCREEN-ERR-05` 网络中断或离线 | 连接不可用 | 提示离线与能力限制 | 重连后恢复/查询 | 声称整个站点具有离线写入能力 |
| `SCREEN-ERR-06` 数据过期或冲突 | 编辑期间底层事实已变化 | 显示新旧关键差异；旧核对失效 | 重新读取并确认 | 静默覆盖另一端新数据 |
| `SCREEN-ERR-07` 来源失效 | 跨域来源删除/权限变化/不可定位 | 对已成功的目标操作仍给出准确结果；独立提示来源不可返回 | 返回安全业务入口 | 错称交易失败、泄露已失效来源详情 |
| `SCREEN-AUTH-01` 登录状态过期 | 会话失效，需要重新验证身份 | 清晰说明需要重新登录，避免泄露保护信息 | 前往重新登录 | 用“无记录”替代授权失效 |
| `SCREEN-AUTH-02` 无权限访问 | 对象不属于当前用户或无访问许可 | 通用无权限反馈，隐藏对象敏感信息 | 返回本人模块首页 | 显示其他用户的数据标题、账户、金额 |
| `SCREEN-AUTH-03` 页面/资源不存在 | 已删除或错误链接 | 通用不可用提示、安全入口 | 返回模块/首页 | 推测目标是否属于其他用户 |

对于 `SCREEN-AUTH-02` 与 `SCREEN-AUTH-03`，可以按隐私策略向非授权用户使用同样的“无法访问此内容”外观，避免通过文案区分资源是否存在。上述方案是界面行为设计，不指定未来接口返回的状态码。

### 3.2 登录过期时的未保存内容

- 已确认保存的数据不应因为登录过期而被标记丢失。
- 对本页尚未确认保存的输入，界面应清楚说明风险；能够安全保留时暂时保留原编辑上下文，身份重新验证成功且仍具权限后再引导用户核对、提交。
- 不得将私有字段长期暴露给退出登录后的另一用户，也不承诺跨浏览器/设备离线恢复未保存草稿。
- 若重新认证后权限发生变化，拒绝继续提交并给出安全入口。

### 3.3 跨模块来源失效：区分业务事实和返回路径

举例：用户从饮食采购清单打开经济记账并成功提交，但在返回前采购清单被删除或权限改变。

1. 目标结果页仍可以说“这笔财务交易已保存”，前提是它确实成功并属于当前用户。
2. 不再显示无法访问的采购清单内容，不自动把交易关联到其他清单。
3. 解释“原来源当前不可访问”，提供“查看该笔交易”及“返回经济首页”。
4. 如果财务交易本身结果未知，则优先核对同一笔提交状态，而不是把来源失效误写成交易失败。

## 4. 手机端专门规则

| 场景 | 设计规则 |
|---|---|
| 小屏 320–390px | 一级导航固定，领域标签可横向滚动；不强制把过长文案塞进一行 |
| 首次欢迎 | 单栏可扫读卡片，最多一个强调性的主动作；跳过入口清晰可见 |
| 空状态 | 首屏说明“为何为空”和行动入口，不强制滚动很长才能开始 |
| 底部表单 | 虚拟键盘出现时主按钮和错误字段可达，不被底部导航覆盖 |
| 系统异常 | 对于可恢复错误优先原位反馈；身份过期/无权访问用清晰独立页面 |
| 保存失败 | 输入内容仍在视野和上下文中；重试按钮至少满足推荐触控面积 |
| 身份变更 | 遮蔽敏感原数据；避免注销后从后退历史看到其他账户的私有详情 |
| 屏幕阅读器 | 错误说明与字段关联、焦点进入错误标题或字段，可键盘/读屏访问 |
| 视觉动效 | 骨架与保存反馈不过度闪烁，遵循减少动态效果偏好 |

建议以 **320px、360px、390px、430px** 宽度以及 200% 文字缩放进行视觉检查。以上是设计检查档位，不意味着这些尺寸已经实测通过。

## 5. 统一微文案与按钮词汇

| 触发情况 | 标题 / 说明 | 操作 |
|---|---|---|
| 首次登录 | “从一件小事开始。不用一次设置好所有模块。” | “开始记录”“暂时跳过” |
| 财务无账户 | “还没有可用账户。先建一个账户，再记录真实收支。” | “新增账户” |
| 任务筛选无匹配 | “当前筛选没有匹配的任务。” | “清除筛选” |
| 数据加载失败 | “暂时无法获取数据。当前信息可能不完整。” | “重新加载” |
| 保存失败 | “修改还未保存成功。当前输入已保留，请重试。” | “重新保存” |
| 提交结果未知 | “尚无法确认本次操作结果。请先核对，不要重复提交。” | “核对结果” |
| 登录过期 | “登录状态已过期。请重新验证身份后继续。” | “重新登录” |
| 无权限或资源不存在 | “无法访问此内容。可能已失效或当前账户没有权限。” | “返回安全页面” |
| 来源失效但目标成功 | “操作已完成，但原来源目前无法访问。” | “查看已完成记录”“返回模块首页” |

成功、失败、未知结果是互斥的事实陈述；不能用同一句“已完成/请重试”覆盖不同状态。

## 6. 屏幕责任与验收索引

### 6.1 设计屏幕清单

| 屏幕族 | ID 数量 | 优先级 | 核心设计对象 |
|---|---:|---|---|
| 首次使用 | ONB-01～04，4 张 | P0：可跳过、领域最低配置；P1：欢迎视觉细节 | 欢迎、选择、金融前置、完成返回 |
| 空状态 | EMPTY-01～15，15 张 | P0：空/零/失败真实区分；P1：模块引导文案 | 首页及四领域关键空状态 |
| 系统异常 | ERR-01～07，7 张 | P0 | 加载、保存、结果未知、离线、冲突、来源失效 |
| 权限与会话 | AUTH-01～03，3 张 | P0 | 登录过期、无权限、资源不存在 |

**合计 29 张状态屏幕规格**。这是屏幕规格/状态样式的覆盖计数，不等于绘制完成 29 张完整高保真稿。

### 6.2 新增设计验收用例

| 用例编号 | 等级 | 触发或模拟步骤 | 预期结果 |
|---|---|---|---|

## 7. 交接状态、未决事项与后续工作

### 7.1 当前已明确的设计规则

- 欢迎可跳过；按模块渐进初始化；普通任务、自由运动、实际用餐无需全面初始配置。
- 真空、真零、筛选无匹配、局部失败、全页失败都有独立页面语义。
- 权限拒绝与资源不存在不得泄露对象存在性；登陆失效与无数据不能混淆。
- 手机可滚动领域标签，操作按钮与错误恢复入口保持可达。
- 来源失效不推翻已真实成功的目标业务操作。

### 7.2 尚需视觉/技术分别处理

**视觉与产品设计仍需完成**：29 张状态屏幕的全尺寸视觉检查；欢迎返回路径与首次操作完成后的实际文案评审；数据遮蔽的细粒度审阅；与 05 文档中的财务、训练、采购异常场景去重对齐；键盘与系统字号放大后的交互检查。

**未来技术评审尚未开始**：鉴权与会话生命周期；多设备编辑冲突版本策略；草稿保护与登录失效边界；数据加载与缓存失效策略；关键操作幂等核验与状态查询；审计日志与授权防护。

**不在本轮确认** 任何后端技术栈、URL 路由、数据库表、API 格式、缓存结构或具体实现细节。
