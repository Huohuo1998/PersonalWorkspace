> 文档状态：**核心视觉决策已确认、V2.0 基线生效**；高保真边界状态及设备适配仍需设计验收。

## 1. 产品定位与范围

Personal Workspace 是个人优先、未来可扩展多用户且严格数据隔离的生活工作台，五个全站一级入口为 **Dashboard、日程、经济、运动、饮食**。个人设置属于辅助入口。业务模块拥有各自记录的事实来源；日程集中展示任务与事件，不伪造其他领域实际记录。

**MVP 不包括：** AI 自动生成新食谱或强制健康建议、穿戴设备/银行自动同步、完整厨房库存、复杂热量营养核算、共享账户与协作、自由布局首页、全局通用目标/习惯平台。未来扩展不影响当前业务归属。

## 3. 全站信息架构

| L1 模块 | L2 主视图 | L3 典型界面 |
|---|---|---|
| Dashboard | 首页 | 今日行动、快捷新增、四领域摘要、待关注、隐私开关 |
| 日程 | 今日／收集箱／任务／日历／项目 | 任务详情、事件详情、重复实例调整、项目详情 |
| 经济 | 概览／交易／账户／预算／储蓄 | 记账、转账、还款、退款、余额校正、关联交易详情 |
| 运动 | 概览／计划／训练／历史／身体 | 动作库、训练模板、逐组训练、恢复/结束确认、体征及恢复记录 |
| 饮食 | 概览／食谱／菜单／采购／记录 | 食谱详情、周菜单编辑、采购差异、实际用餐详情 |

- L1 统一：桌面固定左栏，手机固定底部五入口；所有一级入口易辨识。
- L2 统一：桌面标签或明确的二级导航；手机可滚动标签栏，选中状态始终清楚。**不得强行挤压五项标签至不可触控。**
- L3 统一：桌面轻量录入可弹窗/侧面板，复杂详情可右侧抽屉/独立页；手机轻量录入可底部面板，复杂编辑独立页；持续训练使用专注模式。
- 从跨域来源打开 L3 时必须显示来源关联并提供安全返回；目标保存/取消后的返回行为一致。

| color.border.default | `#E3E8EF` | 边界、分隔 |
| color.state.success | `#137A5A` | 已确认成功、已完成 |

| color.state.danger | `#B42318` | 操作失败、破坏性动作 |
| color.state.info | `#2563A6` | 非危险信息及事件辅助色 |

基本对比度已通过数值预核对：`#256B5F` 对白色约 **6.27:1**，`#586473` 对白色约 **6.03:1**，`#586473` 对页面底色约 **5.67:1**。这**不代替**完整的组件状态/图标/焦点/图表可访问性验收。

颜色不能是区分 Task、Event、失败、完成、预算超支或过敏原的唯一依据；必须配合文字和/或图标。普通消费不默认标红，休息日不以“失败”呈现。

### 4.2 字体与排版

- 中文优先系统字体：PingFang SC、Microsoft YaHei、Noto Sans CJK SC、system-ui 及后备字体；不需要外发字体文件。
- 页标题 24–28px；区块标题 18–20px；卡片标题 16px；正文 14–16px；移动正文优先 16px；辅助 12–14px；核心金额/测量统计 24–32px。
- 正文行高约 1.5，标题 1.2–1.35；重要金额、重量、时长使用等宽数字并标清单位。
- 信息层级：页面标题 > 当前主要操作/今日行动 > 核心数据 > 辅助提示；不使用过多同等权重的彩色卡片。

### 4.3 空间、容器与布局

- 间距采用 4px 倍数：4/8/12/16/24/32px。
- 输入框/按钮圆角 8–10px；普通卡片 12px；大型容器/面板约 16px；以轻边框为主。
- 桌面侧栏目标约 224px；主内容最大约 1280px；页面水平留白约 24px；卡片间距 16–24px。
- 手机页面水平留白约 16px，单列优先，操作触控区优先至少 44×44px。适配安全区域、软键盘、系统字体放大和窄屏；固定操作区不得盖住输入字段。
- 不将参考线框图的精确像素视为设计验收合格证据；屏幕/放大字号仍需要专门验证。

## 5. 全站组件与状态协议

### 5.1 组件族

Navigation（L1/L2/返回）、Page Header、Card/Stat、Task Row、Event Row、Transaction Row、Recipe Card、Grocery Row、Workout Set Row、Form Field、Numeric+Unit、Date/Time Field、Tabs、Filters、Drawer、Bottom Sheet、Dialog、Progress、Toast/Inline Alert、Empty State、Error State、Skeleton、Privacy Mask。

### 5.2 保存模型（沿用 SYS-UX-D01）

| 模型 | 适用示例 | 视觉反馈与关闭约束 |
|---|---|---|
| 即时提交 | 勾选普通任务、采购已购状态 | 可乐观展示但必须有失败回滚/提示 |
| 显式提交 | 记账、食谱/预算编辑、交易更正 | 提交中防止重复；服务器确认后才显示成功 |
| 过程自动保存 | 详细训练逐组记录 | 常驻 saving/saved/failed；最终结束必须另行确认 |

**统一语义**：loading ≠ empty ≠ zero ≠ saving ≠ saved ≠ failed。失败后尽可能保留输入和原上下文，并提供重试；成功提示应短暂但可感知。

### 5.3 内容隐私

敏感汇总**默认显示**，提供一键遮蔽并按用户保存偏好。遮蔽涵盖金额、预算比例/趋势、可能反推出金额的进度图、说明文案、悬浮提示、摘要通知；其他被产品定义为敏感的身体测量等字段亦按一致原则处理。此功能不替代鉴权与多用户数据隔离。

## 6. 各领域强制视觉规则

### 6.1 Dashboard

- 首屏：有时间的任务/事件依时间排序；全天项独立；无定时但今日截止或手动提升的任务进入“今日重点”。逾期任务单列关注，不能默默改成今天排期；完成任务可折叠。
- 独立 Event 不展示任务完成勾选、不计入任务完成率。摘要显示真实来源，避免以计划代替事实。
- 桌面以今日行动为主内容、快捷入口和待关注为辅助；手机顺序：今日行动 → 快捷操作 → 领域摘要 → 待关注。
- 首页布局 MVP 固定，不提供自由拖拽定制。

### 6.2 日程

- 收集箱是**组织位置**而非任务状态；标题可单独快速录入。TODO/IN_PROGRESS/COMPLETED/CANCELLED 状态语义不受位置改变。
- 日期输入严格区分 Scheduled（执行）和 Due（截止）。截止日期本身不形成全天时间块，选择“安排今天”要进入今日重点。
- 独立事件显示明确时间及 Event 标识，不参与任务完成率。领域任务的“进入专业模块执行”入口应突出，但手动勾任务不产生领域实际记录。
- 单次重复实例改期不修改源模板；领域长期计划修改从来源模块进行。
- SCH-VIS-D01～03 统一生效。

### 6.3 经济

- 概览首层展示资产账户总额、信用负债、净资产参考值；随后是当月真实收入/净支出；预算及最近流水为次级。
- 信用卡购买：增加负债，并计一次当期支出；还款：减少真实资产和负债，**不能**再次计支出。
- 自有账户转账不计收入或支出；退款关联原始交易，按退款实际发生月份抵减对应分类净支出；余额校正保留原因/历史且不混入正常收入。
- 预算剩余额度不是实际银行余额，分类预算属于总预算配置而非二次叠加；储蓄进度绑定真实专用账户，避免重复归属。
- 普通记账轻量化；高风险操作核对账户、金额、日期、影响口径、不可逆性和来源关联，并防重复提交。
- FIN-VIS-D01～03 统一生效。

### 6.4 运动

- 概览优先今日训练和恢复入口；计划页含动作库/模板；训练执行以当前动作、实际重量/次数/时长、逐组完成为主。
- 同一用户同时只能存在一条 IN_PROGRESS 或 PAUSED 的**详细训练会话**，但一天允许多个已结束记录；快速有氧记录不必占用该持续会话。
- 逐组自动保存并展示真实确认状态；结束训练核对已完成组数、未完成组数和结局（完成/中止），不得自动把计划组数记为实际组数。
- 手机固定操作区和断点恢复为重点；跨设备编辑冲突不得静默覆盖；模板变动不得改写历史。
- FIT-VIS-D01～03 统一生效。

### 6.5 饮食

- 食谱重点：图片、菜名、时间、已知食材/过敏原、操作；仅对已知信息做条件筛选，未知配料不能保证无过敏原。
- 菜单：桌面七日三餐整体视图，手机单日三餐切换；自由文本菜单不强制建食谱，也不自动伪算食材。
- 采购：从结构化食谱与份数汇总需求，仅合法单位换算；生成后独立快照，菜单修改展示差异。保护人工修改、已购条目；增加需求时需展示补购建议，减少需求不得删去已购事实。
- 从菜单进入用餐记录仅**预填**，经用户确认才写入真实 Meal Record。自炊统计来自已记录的真实用餐来源；采购勾选不自动生成消费。
- DIET-VIS-D01～03 统一生效。
