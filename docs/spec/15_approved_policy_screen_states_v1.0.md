## 2. FIN-S01｜负余额交易核对

### 页面 1：轻量记账

- 金额、真实发生日期、支出分类和账户按既有轻量录入展示。
- 示例：现金账户 ¥50，支出 ¥80；用户点击保存时不可直接默默成功，也不可直接禁用“真实支出”。

### 页面 2：异常核对（桌面独立核对面板；手机全屏确认）

```text
即将产生负余额
账户：随身现金
本次支出：¥80.00
提交前余额：¥50.00
预计余额：−¥30.00
请核对账户、交易日期和金额是否与实际一致。
[返回修改]  [确认已真实发生并记录]
```

- 警示图标与文字并用；预计余额保留负号，不能显示绝对值代替负数。
- 保存成功后仍以交易事实和真实余额展现；账户卡片附“负余额，请核对”，提供进入账目历史/余额校正的入口。
- 若账户余额在核对期间因另一笔交易变化，应显示新的预计余额并要求再次核对。

### 禁止

- 强制构造 ¥30 收入、“自动借款”、把已发生交易丢进无原因失败态。
- 用预算剩余额度抵扣现金账户负数。

## 3. FIN-S02｜信用卡溢缴款

### 编辑与核对

```text
信用卡还款
还款账户：工资银行卡
信用卡当前待还：¥500.00
本次真实还款：¥600.00
预计还款后：欠款 ¥0.00 / 溢缴款 ¥100.00
本次不增加消费或收入。
[返回修改]  [确认真实还款]
```

### 结果与概览

- 信用卡卡片显式显示“待还欠款 ¥0”“溢缴余额 ¥100”，不能展示“-¥100 欠款”造成含义不清。
- 资产汇总、信用负债和净资产参考值只计算一次卡内溢缴；当溢缴被后续正常消费抵扣时，消费依然计当月支出。
- 提交未知状态进入统一交易核对流程，禁止重复还款；若实际付款账户余额同时为负，还要执行 FIN-S01 的资金核对规则。

## 4. FIN-S03｜跨账户退款

### 退款详情

```text
退款原交易：10/05 · 耳机配件 · 信用卡消费 ¥320
已退款 / 剩余可退款：按真实已关联退款展示
实际退款金额：¥100
实际到账日期：2026-10-12
原支付账户：信用卡
实际到账账户：[现金账户 v]
[继续核对]
```

### 确认界面

- 显著标注“本次退款到账账户不同于原支付账户”。
- 展示**实际现金账户 +¥100**、**原信用卡账面无变化**、**当月数码类净支出 −¥100**。
- 不展示虚假的信用卡欠款减少，若退款真到信用卡才影响信用卡账面状态。
- 退款累计额度在核对与提交时均应被可靠校验；提交中不接受第二次相同操作。

## 5. DIET-S01｜食材安全单位合并

### 可直接汇总

```text
大米：1 kg + 500 g = 1.5 kg
牛奶：1 L + 250 ml = 1.25 L
```

### 需要人工核对

```text
番茄：2 个（规格未知）
番茄：200 g
状态：单位不可直接换算，保持两条采购需求。
[保持分列] [核对本次采购]
```

- “待人工核对”不能在没有用户确认的情况下改变全局食材单位规则。
- 若自定义菜名缺少结构化食材，显示“该餐无法生成可靠采购需求”。

## 6. DIET-S02｜采购清单版本差异和多轮补购

### 新增需求

```text
当前已购：鸡蛋 2 个  ✔ 已购买
当前未购：0 个
新菜单理论需求：4 个
建议补购：2 个
[忽略本轮变更] [确认新增待购 2 个]
```

### 后续增加需求（之前补购仍待买）

```text
已购：2 个；已安排未购：2 个
新菜单需求：5 个
需要额外安排：1 个（非 3 个）
[核对明细] [确认更新未购补购行为 3 个]
```

### 需求减少

- 已购 4 个、新需求 2 个：保留已购 4 个，显示“现有采购高于本次菜单需求”；绝不生成“负补购”。
- 未购人工改量 3 个、新需求 4 个：保留用户修改；如仍需处理增量，用独立差异展示，不默默覆写 3 为 4。
- 再次核对同一菜单版本/同一已应用差异，不得新增重复补购。
- 若单位不同或规格模糊，显示“无法确定补购量”，禁止基于错误换算生成待购项。
- 已购记录只是实际采购执行，不自动成为厨房库存余额，也不自动生成经济消费交易。

## 7. PRIV-S01｜全站隐私遮蔽矩阵

| 区域 | 未遮蔽 | 隐私模式 | 必查风险点 |
|---|---|---|---|
| Dashboard 资产/预算摘要 | 真实金额/比例 | 数字与可反推说明都隐藏 | 通知、标签、百分比进度 |
| Finance 账户/交易/储蓄 | 金额与资金走势 | 数值、图表坐标/tooltip 等隐藏 | 交易列表副标题、余额更正预览 |
| Fitness 概览/历史 | 训练表现统计 | 表现数值与可推断摘要隐藏 | 最近训练、最高负重、趋势 |
| Fitness 身体/恢复 | 体重腰围/恢复状态 | 指标、主观恢复详情及趋势隐藏 | 图表 y 轴、悬浮提示 |
| 系统消息与错误通知 | 适度引用对象细节 | 不在被动文案泄露敏感值 | Toast、操作摘要、浏览器页面摘要 |

**视觉要求：** 遮蔽后的卡片布局稳定，可提供“数值已隐藏”，不得误示为 0 或空值；只提供摘要状态而不外显能反推出值的分段阈值。

## 8. PRIV-S02｜隐私模式下的主动编辑

- 用户点击“编辑这笔记账”或进入“开始/继续训练”或新建身体测量，明确进入**主动操作表单**时，该表单的本次金额/重量/次数/体重输入仍可见可编辑。
- 其他摘要卡片、历史列表、已保存状态信息仍遵守全局隐私模式。
- UI 可轻提示“本次操作的输入值会显示在屏幕上”；退出编辑后，全局隐私仍开启。
- 临时查看被动详情不视为自动解锁；若将来提供局部查看开关，其有效范围与复原需要单独设计确认。
