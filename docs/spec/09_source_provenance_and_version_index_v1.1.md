## 1. 目的与证据等级

为防止未来把“原始 PRD”“后来归纳的产品规则”“视觉原型中的示例”“待审批的建议”混为一谈，统一使用以下证据标记：

| 等级 | 名称 | 判断标准 | 允许用途 |
|---|---|---|---|
| A | 原始已确认文件 | 能取得当时确认版本的完整、可审阅正文及来源信息 | 原样归档、作为直接基线 |
| B | 已确认决策记录 | 对话中可明确追溯用户认可的决策，或现行正式基线中的已确认项目 | 作为冻结约束，但不能冒充完整原稿 |
| C | 基于确认内容的重述稿 | 从已确认决策和现有交接文档整理出新文档，并清楚标注重述来源 | 辅助评审、后续经逐条确认才能变成独立定版原文 |
| D | 提案 / 待决策 | 尚无用户最终批准的候选规则、视觉细节或补充政策 | 提交专项审批，不得擅自冻结 |
| E | 设计示例 / 虚构数据 | 交互演示、虚构余额、运动次数、食材量、占位图片 | 仅作呈现示例，不构成业务规范 |

对每条需求，推荐记录：`source_title / source_version / source_status / decision_id / effective_date / owner / related_screen / acceptance_case / change_history`。这些是**文档追溯字段建议**，不是确定的数据库/API 设计。

## 5. 已确认决策的分层归属

- **业务 PRD 层**：五个一级模块、领域真实事实的所有权、任务不伪造交易/运动/饮食、实际日期与财务审计、采购/食谱边界。
- **UX 层**：各专业五个主视图、任务与事件的不同交互、轻量化录入、逐组训练自动保存、采购快照差异确认、全局快捷入口和跨模块来源返回。
- **视觉层**：Calm Workspace、桌面/手机呈现、类型图标/文字、财务风险核对、训练专注模式及采购勾选视觉。
- **未决业务规则层**：参见 `11_product_policy_review_proposals_v1.0.md`。不得因位于新文档内而自动视为已确认。
- **未来技术层**：认证/数据隔离的技术方案、事务与审计存储、版本冲突/幂等协议、API、数据库、部署等尚未开始。
