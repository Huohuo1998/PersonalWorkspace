## 2. 全站产品定位与业务约束

### 2.1 目标与范围

建设一个个人优先、预留未来多用户但不同用户的数据严格隔离的 Personal Workspace。五个一级入口：**Dashboard、日程、经济、运动、饮食**。个人设置在辅助入口。个人用户可以仅启用部分模块开始使用。

MVP 不包括：AI 全自动教练/新食谱生成、银行/穿戴同步、多人协作与共享资金、完整厨房库存、强制卡路里及宏量营养核算、通用目标/习惯平台、自由拖拽布局。

### 2.2 事实与计划分离

- 日程管理 **Task / TaskOccurrence / Event / Project**；业务执行计划由专业领域拥有来源。
- 经济 **Transaction、Refund、Adjustment**；运动 **WorkoutSession、WorkoutSet**；饮食 **MealRecord** 是专业领域真实发生的事实。
- 勾选普通任务不会伪造交易、训练或用餐；采购勾选不会伪造支付；安排菜单不会伪造吃过这餐。
- 专业领域确认实际完成时，若有明确稳定关联，可以更新相应日程实例；不能修改原领域长期计划，更不能以任务名称模糊匹配。
- 跨模块操作保留来源对象、执行实例、日期/筛选等页面上下文；成功/取消合理返回；来源失效则保留目标已成功的业务事实并安全返回。
- 用户隔离、必要历史、错误/保存反馈与恢复机制属于 P0 需求。

## 3. Dashboard 重述

### 3.1 信息架构

- 首页第一层显示当日有开始时间的任务/事件，以时间排序；全天项独立。
- 无固定时间但今日截止、或用户明确提升至今日的 Task 放入“今日重点”；逾期事项单列提醒，不自动改排期。
- Event 不展示 Task 完成勾选，不纳入任务完成率；普通已完成 Task 可折叠。
- 快捷「+」统一进入任务、事件、记账、运动、饮食专业表单，不创建平行的第二套流程。
- 四领域摘要使用真实来源，不把预算计划/训练安排/菜单计划当作实际发生结果；缺数据、零值、加载失败必须分别处理。

### 3.2 隐私和布局

- 敏感摘要**默认显示**；用户可以一键遮蔽，偏好随用户保存。完整遮蔽范围见第 9 节，以及已批准的 `POL-PRIV-01`。
- MVP 首页布局固定；桌面以今日行动为主列、快捷入口及提醒为辅助，手机依次为今日行动→快捷入口→领域摘要→待关注。

## 4. 日程重述（Schedule）

### 4.1 视图与对象

五主视图：**今日、收集箱、任务、日历、项目**。

- 收集箱属于组织位置，不是 Task 的另一种执行状态。输入标题即可捕获，可稍后分类、设置项目、优先级、时间。
- Task 状态：`TODO / IN_PROGRESS / COMPLETED / CANCELLED`。逾期、今日、延期、收集箱属于派生分类或组织属性。
- Task 的 **Due（截止）** 与 **Scheduled（计划执行）** 必须独立编辑。仅有截止日期的 Task 不被画成占据完整时间段的日历事件。
- Event 与 Task 独立，拥有开始/结束/全天语义，不要求完成勾选。
- 允许简单重复任务；重复模板与单次生成实例独立。修改某次实例不静默影响未来，源领域长期计划需从来源模块调整。
- 轻量项目用于任务组织，非复杂企业项目管理。

### 4.2 视觉与交互

- 今日：定时事项时间线 + 无定时今日重点；用户“安排今天”应真正进入今日重点，即便未设置 Due。
- 桌面日历可以完整呈现日/周/月时间结构；手机按日期日程列表优先，独立 Event 与 Task 用图标+类型文字+低饱和颜色共同标识。
- 桌面 Task 详情为侧边抽屉，手机为独立详情页；领域 Task 优先提供“进入来源执行”，手动完成仍不生成领域事实。

## 5. 经济重述（Finance）

### 5.1 五个视图与基础对象

五主视图：**概览、交易、账户、预算、储蓄**。账户包括银行、现金、电子钱包、信用负债等；资产与负债分别展示，净资产可作为参考值。

### 5.2 金融事实与口径

- 普通收入和支出计入对应实际日期及分类。
- 自有账户内部转账：两侧账户余额发生实际变化，不计为收入/支出。
- 信用卡购买：产生一次支出，同时增加信用负债；之后还款：减少资产与负债，不重复计支出。
- 退款：关联原消费，保留原交易和历史；按**退款实际发生月份**抵减相应分类净支出。部分退款需要追溯累计金额，不能无意超过原交易可退额。
- 余额校正：展示差额、校正原因和必要审计，不能混入正常收入/支出。关键更正避免无痕覆写真实历史。
- 月度总预算和分类预算是**计划**，分类预算位于整体框架中而非重复叠加；预算剩余额度 ≠ 账户可用余额。
- 储蓄目标通过真实专用资产账户归属，目标金额调整不凭空创造余额；一个专用账户同时最多有一个有效储蓄目标。
- 普通记账简洁录入；内部转账、还款、退款和余额更正是专用核对流程，成功后才提示完成；提交结果未知时优先查原结果，禁止盲目再建一笔。

### 5.3 已正式批准的财务政策（2026-10-12）

- `POL-FIN-01` **方案 B**：如实记录已发生的负资产账户余额；若预计余额低于零，显示负余额与风险核对，允许明确确认，不虚构收入。
- `POL-FIN-02` **方案 B**：信用卡超额还款产生溢缴款；欠款、溢缴分别展示；溢缴视为单次正向余额参与净资产，不重复计收入/支出。
- `POL-FIN-03` **方案 B**：退款默认回原支付账户，也可确认其他真实到账账户；仅改变实际收款账户状态；按实际退款月抵减原分类净支出。
- 核心信用卡算式：`C = 欠款 − 溢缴`（C 可正/负），`待还=max(C,0)`、`溢缴=max(-C,0)`；净资产中溢缴只算一次。详见批准补充文档 `12_approved_product_policy_baseline_v1.0.md` B 节。


## 6. 运动重述（Fitness）

### 6.1 页面与规划

五主视图：**概览、计划、训练、历史、身体**；动作库和训练模板为“计划”的子功能。

允许手工或预置训练计划、周训练安排、运动目标、模板与动作维护；也允许不用计划直接记录步行、跑步、有氧等。目标、计划、实际训练彼此区分；模板修改不能覆写已经发生的训练事实。

### 6.2 详细训练生命周期

- 一条详细训练会话为 `IN_PROGRESS / PAUSED / COMPLETED / ABORTED` 之一；同一用户同一时刻最多一条 `IN_PROGRESS` 或 `PAUSED` 会话，允许同日多条已结束训练。
- 实际重量、次数、时间、组完成与动作调整逐组自动保存。显示 `saving / saved / failed` 且仅在真正保存成功后显示 saved；失败时保留未同步输入并可重试。
- 中断后能恢复已确认保存的训练；多设备编辑冲突不能静默覆盖。
- 结束训练必须再次明确确认，分完成与中止，记录实际完成组数，不把未完成计划组计为实际。
- 从日程进入训练应关联特定实例；只有真实完成并符合相应闭环条件才能更新 Task，不由手动勾任务反推 WorkoutSession。
- 体重、腰围和疲劳/酸痛反馈可选、独立，不强制每日测量或填报。

### 6.3 手机视觉

详细训练使用专注模式，当前动作记录是主内容，底部关键操作固定且留安全区，输入法弹出仍可操作。中断恢复入口优先出现。

## 7. 饮食重述（Diet）

### 7.1 五视图与食谱

五主视图：**概览、食谱、菜单、采购、记录**。食谱可以是预置或用户自定义，包含结构化食材、数量/单位/份量、步骤和可选标签、制作时间；允许选择现有食谱做条件筛选推荐，而非 MVP 自动生成新食谱。已知过敏/偏好用于筛选，不可宣称未知配料绝对安全。

### 7.2 菜单和采购

- 用户可排每日/每周早、中、晚三餐，替换菜品、修改份量或使用自由文本；计划本身不等于真实用餐。
- 采购需求基于结构化食谱乘以份数汇总，**只有可靠等价单位**可以合并；不同单位、配料缺失应保留独立条目或标记待人工核对。
- 采购清单生成后为独立快照。菜单变化不能静默重生成并覆盖既有已购状态与手工数量。
- 差异核对区应列明增加/减少/无法转换/人工覆盖/已购保护；用户确认后应用允许的变化。增加需求时可提出补购建议，减少需求不能删除已购买事实；重复核对不得生成重复补购条目。
- 已购勾选只代表采购执行状态，不生成财务消费；付款必须由经济模块真实记账并形成关联。
- MVP 不维护完整家庭食材库存。

### 7.3 实际用餐

- 快速记录餐次与实际食物，详细记录可选食谱、实际份量、来源和备注；不强制热量/macros。
- 从菜单进入仅预填，在用户确认保存前不创建 MealRecord。自炊统计依据真实记录中用户确认的用餐来源，而非菜单类型。
- 桌面菜单七日全局，手机为单日三餐 + 日期切换；采购采用大勾选区域与独立差异确认。

### 7.4 已正式批准的饮食政策（2026-10-12）

- `POL-DIET-01` **方案 B**：仅自动换算同食材同规格、量纲/比率可靠的 g/kg、ml/L 及可确定相同规格的件数；跨重量/容积/件数不可猜算，未知项人工核对。
- `POL-DIET-02` **方案 B**：新理论需求、已购、未购、人工改量分别保留；用户确认才调整允许的未购自动条目/补购差异；已购历史与手改不静默覆盖，多轮差异不重复新增。详见 `12_approved_product_policy_baseline_v1.0.md` C 节。


## 8. 全站交互语法

| 操作类别 | 通用模式 | 示例 |
|---|---|---|
| 轻量状态 | 即时提交，失败纠正或回滚 | 完成普通 Task、采购已购勾选 |
| 明确提交 | 表单核对后保存，确认持久化 | 记账、预算/食谱编辑 |
| 自动保存 | 输入过程持续持久化，最终操作另行确认 | 详细 WorkoutSet |
| 高风险更正 | 明确对象、影响差额、事前核对、保留历史 | 转账、还款、退款、余额校正 |
| 跨域返回 | 保留来源/日期/筛选/对象标识；来源失效时安全退出 | 采购→记账；日程→训练 |

首登采用可跳过欢迎引导和按模块最低初始化：普通任务只填标题，财务记账先建立真实账户，自由运动/实际用餐不要求先建立计划。所有页面区别 `empty / true zero / loading error / save error / unauthorized / unknown outcome`。

## 9. 视觉基线与隐私

基线设计采用 **Calm Workspace**：青绿色主色 `#256B5F`、页面背景 `#F7F8FA`、白色卡片、主文字 `#17212F`、辅助文字 `#586473`、轻边框 `#E3E8EF`。桌面固定侧栏、手机固定五入口底部导航，二级标签可水平滚动。具有正确文字/图标语义，不仅靠颜色区分状态。

用户敏感摘要默认显示，可按用户偏好一键遮蔽；对资金金额/预算衍生信息/图表/辅助文字的完整遮蔽已确认。**`POL-PRIV-01` 方案 B 已正式批准：** 身体测量、恢复状态、训练表现摘要与财务衍生值一并纳入全站隐私遮蔽；用户主动进入编辑和详细训练时必要的本次输入保持可用。不能因主动编辑而永久关闭全局隐私。详见 `12_approved_product_policy_baseline_v1.0.md` D 节。
